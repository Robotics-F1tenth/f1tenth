# ekf_pose 핸드오프 — control 팀원용 요약 (2026-08-04)

원 질문 "state_ekf.cpp 되살릴까 vs ekf_pose 개발할까"에 대한 결론과, 그 이후
진행한 ekf_pose 개발 내용을 정리. 전체 분석/근거는 `ekf-pose-analysis-2026-08.md`
(700줄+, 필요할 때만 §번호로 찾아보면 됨) — 이 문서는 그중 **당신이 알아야
할 것 + 해야 할 것만** 뽑음.

## 0. 결론: state_ekf.cpp는 죽은 코드, ekf_pose로 계속 간다

als_ros의 `state_ekf.cpp`는 토픽 배선이 끊겨있고(구독 토픽명 하드코딩 불일치),
어떤 launch에도 안 실려있고, IMU 검증도 전혀 안 된 코드. `ekf_pose`는 실차
bag+mocap GT로 정량 검증까지 끝남. **비교할 필요 없이 ekf_pose가 맞음.**

## 1. 지금 뭐가 바뀌었나 (전부 빌드 통과, 실차 동작엔 영향 없음)

**실차 동작에 영향 없는 이유**: 지금 실차 기본 런치(`cuda_mppi.launch.py`)는
여전히 `/newmcl_pose`를 직접 구독함 — `ekf_pose`는 아직 제어 루프에 안 들어가
있음. 아래 변경은 전부 `ekf_pose` 패키지 내부 개선이라 **지금 당장 차 거동을
바꾸지 않음**. 켤 때 뭐가 바뀌는지만 알면 됨.

## 2. 검증된 것 vs 안 된 것

**bag+GT로 검증됨(오프라인)**:
- EKF 전체: raw MCL(ZOH) 대비 위치오차 **-30~35%**, yaw 개선
- 슬립각 추정: RMSE 5.6°→2.5° / 9.2°→5.6°(운동학 공식 자체)

**아직 실차 검증 안 됨** — 다음에 차 탈 때 이거 확인해주면 됨:
1. `kinematic_slip`이 실제로 코너에서 0.05~0.15 rad 범위로 움직이는지 (계속
   0이면 배선 문제)
2. IMU 축 반전이 **지금도** 재현되는지 — `imu_frame_test.py` 재실행 (또는
   그냥 정지 상태 `a_z` 값만 봐도 됨: `/imu/data`가 +9.76 근처면 지금 보정
   맞는 것, +9.81 근처로 바뀌어 있으면 보정 끄고 재검증 필요)
3. `smppi_with_ekf.launch.py` 실제로 뜨는지(2026-08-03에 배선 버그 3개 고침,
   빌드는 통과하나 실차 스모크테스트는 아직)

## 3. 하나 물어볼 것: IMU 마운트 타임라인

당신이 육안으로 IMU 장착이 정상(안 뒤집힘)인 걸 확인해줬는데, 이게 **0730
bag 녹화 당시부터 그랬던 건지, 아니면 그 이후 누가 만져서 지금 정상이 된
건지** 알면 좋겠음. 전자면 "장착은 원래 정상이었고 문제는 드라이버 쪽"이라는
지금 결론이 확실해지고, 후자면 axis 보정을 다시 검증해야 함(위 2번).

## 4. 우선순위 재정립 — 다음 투자는 ekf_pose가 아닐 수도 있음

`assume_zero_vy` 시뮬 실험(n=6, smppi 쪽에서 수행)이 중요한 걸 보여줌:

- vy 품질(B-2)이 S1(코너 파고들기)의 원인이라는 가설, **통계적으로 미확정**
  (n=6으로는 유의성 안 나옴, 20~30회 필요)
- 더 중요한 발견: **완벽한 모델 + 완벽한 vy 상태추정에서도 주행시간의
  24~27%가 트랙 밖.** 즉 상태추정을 아무리 개선해도 안 없어지는 문제가
  더 크게 따로 있음

**그래서**: ekf_pose 자체의 -30~35% 개선은 진짜고 계속 쓸 가치 있지만, "이걸
더 다듬으면 코너 파고들기가 고쳐진다"는 기대는 낮추는 게 맞음. `smppi-diagnosis
-2026-08.md`가 이미 권고한 대로, **다음 큰 레버는 Phase 3(비용함수: barrier
cost, 요구값 기반 그립 페널티)**일 가능성이 높음 — 이건 `smppi_cuda_controller`
쪽 작업이라 이 문서 범위 밖.

**2026-08-04 후반 업데이트 — Phase 3는 이미 착수·완료됐다.**
아래 "다음 실험"으로 적었던 항목 2번(barrier cost 등)은 그 뒤 구현되어 시뮬
A/B(조건당 6회)까지 끝났다. 결과는
`src/control/smppi_cuda_controller/docs/handoff-2026-08-04.md` §6 참고:

- barrier 2000 단독: 거리 117→146m, 이탈 36.2%→14.2% (**속도·안전 동시 개선**)
- barrier + 곡률 속도한계 + 마진 0.15: **이탈 0%**, 시행간 표준편차 27.2→1.2m

즉 "정상조건에서도 24~27% 이탈"의 원인이 비용함수 구조였다는 추정이 실측으로
확인됐고, 이미 기본값에 반영됐다. **남은 시뮬 과제는 아래 1번뿐이다.**

**실차 없이 아직 남은 실험**:
1. `assume_zero_vy` n=20~30 재실행 — B-2 인과관계 확정 (n=6에선 미확정)
2. ~~Phase 3 착수~~ → **완료.** 위 업데이트 참고
